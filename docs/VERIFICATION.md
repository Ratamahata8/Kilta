# Проверки редакции 2 — 8 октября 2026

## Подготовка GitHub Pages демо

По последнему поручению Pages по умолчанию собирает read-only демо без Supabase. URL/key принудительно очищаются. Ограничения входа, загрузок, сохранения и отправки заявок показаны на каждой странице. Инструкция кнопок публикации: [DEMO_PAGES](DEMO_PAGES.md).

Повторно прошли `npm ci` (с writable npm cache облачной среды), typecheck, lint, 6 unit-тестов, production demo build и все 5 браузерных сценариев. Демо-сценарий дополнительно проверяет отсутствие запросов к Supabase. YAML workflow проверен локально: PR не публикует сайт, permissions минимальны; 6 исполнений шага выбора режима подтвердили демо с пустыми параметрами, игнорирование backend-параметров в демо, отказ при отсутствии конфигурации/секретном ключе, подключённый режим с публичным ключом и отказ при неизвестном режиме.

Удалённый workflow и действующий Pages URL не подтверждены: GitHub API в этой среде отвечает `Forbidden`. Это ограничение доступа к API, не результат выполнения workflow. Тариф и Pages settings проверяет владелец в GitHub; видимость не меняется.

## Выполнено в облачной среде разработки

- Установка через `npm ci`, TypeScript, ESLint и production build прошли на Node.js 24.19.0. Сборка — статический `dist/`, по умолчанию base `/Kilta/`. Отдельная сборка под `/` проверена в браузере: прямой hash-маршрут, refresh, изображения и недоступность входа в read-only демо.
- 6 unit-тестов: границы публичной конфигурации, безопасные URL/rich text, валидация цены/даты, ссылки на медиа и оглавление.
- 16 сценариев PostgreSQL: настоящая миграция, RLS/grants, роли owner/developer/outsider/anon, запрет повышения роли, приватные данные, публикация отдельного снимка, защита файлов и связей, конфликт редакций, стабильный адрес документа, восстановление в новый черновик, закрытые заявки, ограничения buckets и идемпотентный seed.
- 5 браузерных сценариев на production builds: 360/768/1440 px, три темы, контраст основного текста, отсутствие горизонтального скролла, клавиатура и refresh hash-маршрутов; отсутствие конфигурации, пустой каталог и сетевой отказ; загрузка двух JPEG с производными WebP, порядок галереи, preview/draft/publish, независимый посетитель и изменение темы; история rich-text документа; PDF в отдельном публичном bucket и ссылка скачивания.
- Дополнительно по вычисленным CSS-переменным проверены 9 сочетаний темы/акцента: основной текст, подписи на фоне/панелях, акцент и пары цветов кнопок имеют контраст не ниже 4.5:1. Десктопная и мобильная главная просмотрены по снимкам production preview.

Все пять браузерных сценариев прошли одним запуском после последних изменений. Они используют подменённый Supabase transport. SQL исполняется в изолированной базе настоящего PostgreSQL, но `auth` и `storage` — тестовые fixtures. Эти проверки **не подтверждают реальную облачную авторизацию, работу Storage gateway и сохранение между устройствами**.

У Vite есть неблокирующее предупреждение: основной JS chunk превышает 500 КБ (около 150 КБ gzip). Админка загружается отдельным chunk по требованию.

## Ещё не проверено с внешними сервисами

Не предоставлены `VITE_SUPABASE_URL` и `VITE_SUPABASE_PUBLISHABLE_KEY`, не подключён управляемый проект с применённой миграцией, owner и отключённым signup. Поэтому не выполнены реальные Auth/Data API/Storage allow/deny, серверные MIME/size отказы, межбраузерное облачное сохранение, смена пароля и backup/restore. Подготовлены `npm run test:live` и ручные сценарии в [SETUP_SUPABASE](SETUP_SUPABASE.md).

GitHub Pages workflow подготовлен, но не запускался. Не подтверждены тариф для Pages текущего private-репозитория, настройки Pages и build variables. Не выполнены фактический frontend redeploy и проверка сохранности облачных данных после него. Видимость репозитория и домен не менялись, приватные материалы не публиковались.

Форма заявок отключена; полной серверной проверки байтов изображений нет. Подробнее о границах реализации: [README](../README.md), резервировании: [BACKUP](BACKUP.md).
