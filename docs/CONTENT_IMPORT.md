# Наполнение и движение KILTA

Данные импортированы из предоставленной папки `kilta-content`, снимок от 8 октября 2026. В read-only демо — 14 изделий и 8 исходных категорий с их slug, точными описаниями, режимами цен (от/точная/по запросу), материалами, текстовыми размерами, годами и выставками. Наличие не выдумано: отображается «Наличие уточняется». Мастерская заполнена по about, два физических шоурума и две онлайн-площадки — по showrooms, два контакта — по feedback. Архивная политика показана с нейтральной пометкой; её извлечение не считается утверждением документа.

## Что подтвердить владельцу

- My space: исходный размер **Ш 1900 × В1900 × Г350 мм** сохранён; высоту автоматически не исправляли.
- LoveKA: исходная запись **1500*400*400 м** сохранена; единицу не заменяли на «мм» догадкой.
- Цены, наличие, сроки, состав цены каминов, материалы, выставки и актуальность адресов/контактов. Сроки и связь конкретных предметов с шоурумами в архиве не заданы, поэтому не придуманы.
- У Kryptos 451 поле `material_text` пустое: сведения о дубе и войлоке сохранены в точном описании, структурированный список материалов нужно сверить.
- Политика содержит старые домены `kilta.ru`/`ikvwood.ru`, сведения оператора и упоминания аналитики. Текст не исправлялся; трекеры и старые формы не перенесены. Оферта не создавалась.

## Проверка архива и изображения

В manifest 102 изображения, фактически в репозитории найдены 100; их SHA-256 проверены, ошибок контрольных сумм нет. Не хватает:

1. `images/e23df7f47ff4-DSC_7737.jpg`: седьмое фото «Сущности». Остальные семь фото сохранены в исходном порядке. Подмена фотографией другого изделия не выполнялась.
2. `images/e05f71023ae4-Airbrush-image-exten.jpeg`: прежнее изображение главной. Hero использует существующее фото шезлонга «Сущность».

Получение этих двух файлов из CDN недоступно в текущей среде (`403 Forbidden`). При получении оригиналов добавьте их в архив и повторите подготовку. Manifest не переписывается, чтобы скрыть пропуски.

Для 84 используемых изображений созданы локальные card/hero WebP (168 файлов, примерно 11 МБ) в `public/kilta`. Aspect ratio и реальные размеры сохранены; ICC корректно переводится в sRGB, насыщенность не усиливается. Дубли одного снимка определяются по SHA-256. В продуктовой галерее `object-fit: contain`, без обрезания изделия. Первый hero eager, остальные изображения/миниатюры lazy; большой следующий слайд загружается по действию пользователя, предыдущий виден до готовности нового.

Переиспользуемая подготовка:

```sh
python3 -m pip install -r scripts/requirements-content.txt
python3 scripts/prepare_content.py
```

Python/Pillow нужны только для повторной подготовки материалов, не для `npm ci`, frontend build или Pages runtime. Генератор сверяет manifest, выпускает `src/content/kilta.generated.json` и выбранные WebP. Оригиналы и source-html остаются в архиве, не копируются в `public`/Pages artifact. URL источников, локальные пути, hashes и дата сохранены в метаданных; посетителю технические пути не выводятся. Browser hotlink, Tilda scripts/трекеры/формы отсутствуют.

## Импорт в существующий Supabase

Backend не менялся; cloud migrations и инфраструктура автоматически не применяются. При подключении примените **обе** SQL migrations по порядку имени. Вторая добавляет размеры публичных изображений и серверную проверку новых текстовых/контактных полей.

В авторизованной админке откройте «Импорт материалов» → «Предпросмотр изменений». Видны будущие новые черновики, сохранённые записи, отличия полей и предпросмотр изделия. Затем выберите локальную папку `kilta-content` с оригиналами и нажмите «Создать только новые черновики». Файлы проверяются по SHA-256, исходники и производные сохраняются в приватном Storage. Демо уже наполнено и не требует этой операции.

`previewImport`/`importDrafts` в `src/content/import.ts` можно повторно использовать с Supabase adapter. Проверяются существующие и архивные строки; запись с тем же типом/slug, источник ранее импортированной переименованной записи и уже созданные глобальные настройки пропускаются. Клиентские правки, активная тема и опубликованные снимки не меняются. Существующее медиа по стабильному UUID не обновляется. Перед каждой записью данные читаются повторно; конкурентный дубль отвергается БД. Upsert, массового удаления и автоматической публикации нет.

Импорт не является общей транзакцией для всех файлов/записей: возможен частичный результат. Интерфейс показывает реальные счётчики и ошибки; повторный запуск после обновления плана продолжает создание отсутствующего. Публикация категорий, затем изделий и остальных записей выполняется отдельно после сверки. Политика всегда создаётся черновиком с отметкой «требуется сверка».

## Анимации и границы проверки

На desktop категории раскрывают натуральный цвет за 420 мс, масштабируются до 1.025 за 650 мс; подпись поднимается на 6 px, стрелка проявляется за 220 мс. Focus-visible даёт то же поведение. На touch и reduced-motion цвет виден сразу. Карточки изделий всегда цветные, масштаб до 1.02; автоматическая смена второго ракурса не включена.

Reveal: одноразовый IntersectionObserver, opacity и 12 px за 450 мс, задержка 50 мс с пределом 180 мс; без постоянного scroll-handler. Без Observer/reduced-motion контент виден. Hero не скрывается. Галерея: crossfade 220 мс, предыдущий/следующий, счётчик, стрелки/Home/End, свайп; lightbox открывается за 180 мс, Escape закрывает, Tab/Shift+Tab удерживают фокус и возвращают его на исходную кнопку.

Реальные Auth/Data API/Storage и импорт в облако не проверены: параметры Supabase не предоставлены. Браузерные сценарии админки используют mock transport; PostgreSQL проверяет настоящие migrations с тестовыми Auth/Storage fixtures. Публикация остаётся через текущий Pages workflow, `main`, режим `demo`.
